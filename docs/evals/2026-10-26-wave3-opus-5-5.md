# Wave 3 targeted plugin evaluation (2026-10-26)

Interview's repaired baseline scored 12/12 with the plugin versus 6/12 without.
AGY and Premortem met the headroom value bar; eight cases still had no headroom.
Triage alone met the loading experiment's behavioral adoption bar, but its frozen
description failed the existing shipping budget. No description variant, fold or cut ships
from this round.

The Interview baseline repair shipped in [PR #1250](https://github.com/boshu2/agentops/pull/1250)
before these trials. Its opening-turn case now uses the same plain-language by-name request
in both arms, with the scenario and four criteria unchanged. Historical slash-command results
are a different baseline and are not pooled here.

## Subject and method

The subject is `plugin/` at commit `47c72b649a7ccf88f3d7fd17adfa70c900397720`,
Git tree `dc8c6f99bfdc0eb0041fbcb775706c8d182d3ff1`. All 243 original package files were
hashed before launch. Copies were kept outside Git; the control retained 31 AgentOps skills.
The runner was Claude Code 2.1.309 with `claude-opus-5-5`, publishing disabled and raw output
kept in protected storage outside Git. Every observed run had a fresh sandbox memory path.
Both arms also included the same two native built-ins, `cc-plugin-agents-md` and
`cc-plugin-plugin-authoring`.

The [headroom registration](../../evals/plugin-eval/plans/2026-10-wave3-headroom.md) and
[loading registration](../../evals/plugin-eval/plans/2026-10-wave3-loading.md) were fixed before
launch. No skill body, description, case criterion or bar was retuned during the round.
All copied case subsets parsed. The evaluator rejected an absolute `--eval-dir` before
execution; case copies were moved inside the external subjects and addressed relatively.
This configuration failure started no model run.

The independent repository grader, `evals/plugin-eval/grade.py`, used one Opus call per
response. Before counted trials, all 34 hand-written passing/failing calibration answers
across 17 cases received the expected grades, plus one passing judge preflight. Four seeded
smoke runs exercised Git and Python without evaluator errors and are excluded from scores.

## Headroom

There were three runs per arm: forced invocation, natural plugin use and no AgentOps plugin.
The native evaluator batches for a case started together; within a `with-without` batch the
runner scheduled the natural runs before the controls. The comparison is forced minus
without. A case is informative only at a no-plugin score of 0.70 or below; on an informative
case, a gain above 0.15 meets the registered value bar. Scores exclude the deterministic
`skill-loaded` grader. Wilson intervals for each arm, Newcombe difference intervals, Fisher
p-values, per-criterion counts and reference-read receipts are in the companion scorecard.
Pooled criteria within one response are correlated, so these statistics are directional.
Statistics were computed with SciPy 1.18.1.

AGY and Premortem clear the value bar on informative cases. Eight cases have no headroom;
that is not evidence that their skills have no value. The claim-audit case is informative but
misses the gain bar. Navigate's numerical bar clears, but its legacy control still asks for
an unavailable slash command. All three controls explicitly said the command was unavailable
and then answered manually. This is a reproduction of that legacy setup, not a clean
plain-language baseline or evidence of general Navigate benefit.

*AGY grading sensitivity.* The machine judge credited c4 in all three forced replies. In a
manual spot-check, two replies proposed longer fresh timeouts without explicitly deriving
them from the remaining deadline. The machine grades are preserved. Removing all three c4
credits conservatively gives 12/15 versus 6/15, a +0.40 difference: the keep decision survives.
This spot-check also shows why passing extreme calibration answers does not prove that the
judge handles every borderline answer correctly.

Three cases meet the registered revision-candidate rule (a criterion missed in at least two
of three forced runs): Agent Native c3/c4 (resolved, case-folded scope checks and whole-batch
readiness), claim audit c4 (no overall readiness verdict), and Navigate c3/c5 (separate open
scope from ruled-out work and leave historical uptime to the caller). These are observations
under the fixed rubrics, not tested repairs. A repair needs its own accepted rerun bar and
resource envelope.

## Interview's repaired baseline

Interview loaded on 3/3 treatment runs. It scored 12/12 with the plugin and 6/12 without,
a +0.50 difference [95% +0.15, +0.75], Fisher p=0.0137. Every control answered the same
plain-language request; none had to handle an unavailable command. The controls missed the
one-question and recommendation/tradeoff criteria. This measures only the opening turn,
not a complete interview dialogue or the quality of the resulting goal.

## Loading

Each skill ran C (unchanged control), D (its one registered description variant) and L
(the control minus `using-gc`, `agy-native` and `reverse-engineer`). Each subject had six
natural behavior runs and seven weighted historical blind requests. The variant author had
seen the historical requests, so these are not unseen holdouts for the new descriptions.
Loading means an observed matching Skill tool call. Successful tool-result receipts were
also checked. Behavioral scores use the independent Opus grader.

| Skill | C: natural; blind | D: natural; blind | L: natural; blind | C to D behavior | D vs C pooled Fisher p | Behavioral adoption bar |
|---|---|---|---|---|---:|---|
| implement | 0/6; 0/7 | 0/6; 7/7 | 0/6; 0/7 | 9/24 to 12/24 | 0.00522 | misses natural loading |
| triage | 0/6; 4/7 | 4/6; 7/7 | 0/6; 4/7 | 12/30 to 17/30 | 0.0154 | meets all three conditions |
| security | 6/6; 1/7 | 2/6; 6/7 | 6/6; 1/7 | 36/36 to 24/36 | 1 | misses natural loading and loses 0.33 in behavior |
| review | 0/6; 3/7 | 0/6; 5/7 | 0/6; 3/7 | 21/24 to 23/24 | 0.673 | misses natural loading |

L had the same natural/blind totals as C for every skill; its pooled Fisher p was 1 in all
four comparisons. No L subject met both loading thresholds. Security's control never loaded
Reverse Engineer, so the registration's specific competitor-removal confound was not observed.
None of the eight neighbour probes loaded the variant's skill instead of the neighbour;
six loaded their own skill and two loaded none.

The registration labels a failed adoption bar as "listing-bound". These results do not
establish that causal explanation: D changed blind loading, while L did not change the
aggregate totals. Implement went from 0/7 to 7/7 blind loads without changing listing entry
count, and Security traded natural loading and behavior for blind loading. Request shape and
wording matter here. Keep the registered adoption decisions separate from that broader label.

## Scope and limits

This is a targeted rule-adherence experiment, not a full-suite rerun, engineering-outcome
comparison, AGY execution test or interview-dialogue study. Cases were written from the
skills' own rules. Forced results combine an explicit invocation with the installed skill;
loading and reference access must be read beside scores. The machine scorecard preserves
all observed grades, including the AGY credits disputed above.

Three runs per headroom arm and six natural/seven blind loading runs detect only large
changes. A zero-crossing interval does not establish equivalence. For scale, a separate
independent binary endpoint near 50% would need roughly 175 runs per arm to detect a
15-point difference at 80% power and a two-sided 5% level; correlated criterion-runs are
not that endpoint. No extra trials were added to chase significance.

Other models and runtimes, real user outcomes, full dialogue behavior and the effect of
actually folding or deleting a skill were not checked.
