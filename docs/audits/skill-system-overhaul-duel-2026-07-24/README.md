# SOL/FABLE skill-system plan duel

## Result

The duel did not select either sealed proposal wholesale. It produced a
synthesis that keeps SOL's exact-kernel and executable-contract foundation,
FABLE's vocabulary and taxonomy discipline, both wizards' portfolio recut, and
the strongest blind spots from each.

The resulting authoritative migration plan is
[Skill system overhaul plan](../../plans/2026-07-24-skill-system-overhaul.md).
The parallel product review is
[Go CLI deep audit](../2026-07-24-go-cli-deep-audit.md).

The decisive change from the pre-duel plan is ordering: repair and activate the
four-skill exact-byte proof kernel before teaching the whole catalog a richer
metadata contract.

## Method

The duel used:

- SOL: `gpt-5.6-sol`, xhigh reasoning;
- FABLE: `claude-fable-5`, max reasoning;
- the same launch-time evidence packet and SHA-256 ledger;
- sealed independent proposals before either wizard saw the other;
- blind cross-scoring;
- reveal and reaction;
- rebuttal;
- opponent steelman; and
- a final blind-spot pass after both complete argument chains were visible.

The NTM session used `--no-recovery` so neither wizard inherited stale session
context. An initial session that accidentally exposed recovery context was
interrupted, destroyed, and excluded before either accepted duel output. The
clean session was destroyed after both blind-spot artifacts were captured.

`FROZEN_PACKET.sha256` records the exact pre-duel inputs. The final plan now
differs intentionally from the launch-time plan hash; the ledger is preserved
as provenance, not rewritten after synthesis.

## Verified findings that changed the plan

### Exact identity is currently incoherent

SOL found that RPI hashes canonicalized JSON while Validate hashes exact intent
bytes. FABLE independently re-read the producer, consumer, and unit test and
confirmed the mismatch. The RPI mock returns RPI's own digest, masking the
composed failure.

Ruling: the first semantic tranche is exactly `rpi`, `plan`, `implement`, and
`validate`. It starts with a composed RED witness and adopts single-mint,
digest-reference transport.

### Proof evolution needs an activation protocol

Both proposals wanted immutable, versioned proof identities. SOL's blind-spot
pass exposed the missing trust transition: a candidate validator cannot issue
the binding judgment that activates itself.

Ruling: every proof epoch is immutable, and
`proof-contract-transition.v1` must be bound by the previously active proof
contract. Candidate results are shadow-only until activation. NOT_PROVEN never
becomes PASS through an implicit validation-only continuation.

### Rich metadata needs one compiler and a taxonomy budget

The wizards converged on primary placement, lifecycle seams, typed authority,
effects, artifacts, trigger polarity, failure behavior, and proof classes.
FABLE correctly identified two vocabulary hazards in the first plan:
`experiment_select` grants caller authority to a skill, and `core_phase`
duplicates the hard dependency graph.

Ruling:

- replace `experiment_select` with advisory `option_shaping`;
- express core membership through the hard graph;
- define `standalone`;
- derive or retire `tier`;
- keep disposition as curation status only; and
- make taxonomy growth a design-review decision, not a new pile of peer axes.

There is one shadow v3 compiler and one live authority. V3 becomes
authoritative only at the all-catalog cutover.

### Publication must preserve the dirty starting state

Both proposals identified shared generator hazards. The final blind-spot pass
showed that their rollback models omitted a third baseline: pre-existing dirty
generated bytes that differ from both HEAD and the last manifest.

Ruling: complete staging is mandatory. Preflight classifies every target,
captures exact bytes/modes/symlink targets, aborts on unowned collisions, writes
the manifest last, and restores only from the recovery bundle. Worker lanes do
not generate shared surfaces.

### Effect declarations need runtime reconciliation

Typed frontmatter can still lie about a child process, external mutation,
credential switch, or failed cleanup.

Ruling: effectful skills emit `effect-receipt.v1`; Validate compares observed
effects with declared and authorized effects. An unobservable required claim
is NOT_PROVEN.

### Local trigger validity does not prove portfolio usability

The initial plan tested skills mostly in isolation. Both later blind-spot
passes showed that 49 locally valid descriptions may still yield broad-skill
dominance, unreachable specialists, alias divergence, or wrong-authority
selection by a stochastic model.

Ruling: capture a pre-change live routing baseline, compile all trigger
fixtures into a global corpus, add a small adversarial cross-product, and
require reachability plus pre/post live-model sampling at cutover.

### Installed estates advance at different speeds

The repository can update a strict Go reader, copied skills, plugins, symlinked
skills, runtime images, and Homebrew binaries on different cadences.

Ruling: v3 is strict when identified as v3, while legacy inputs use a bounded
compatibility branch and deprecation warning. The release-channel audit is a
cutover blocker.

## Resolved disagreements

### Core kernel versus a five-skill campaign atom

FABLE initially grouped `craft-goal` with the four core skills to prevent an
authority gap. SOL argued that caller authority already bridges the migration
and an optional campaign compiler must not become a kernel dependency.

Resolution: SOL's boundary wins. Prove the four-skill kernel first; migrate
`craft-goal` with product, fitness, and advisory admission.

### CLI as prerequisite versus sibling program

SOL initially elevated the audited CLI defects into prerequisite substrate.
FABLE showed that most defects are not on the skill migration's proof path.

Resolution: the CLI gets an expedited three-tranche sibling release program.
A specific defect blocks a skill tranche only when the transitive proof ledger
shows `USED_UNSOUND`. `UNKNOWN` forces NOT_PROVEN; `PROVEN_UNUSED` allows the
skill work to proceed. Filesystem traversal containment remains urgent on its
own security merits.

### `shared`: populate or retire

SOL favored retiring an empty miscellaneous skill. FABLE found six live prose
consumers of shared model-dispatch behavior.

Resolution: do not populate a catch-all and do not delete the live invariant.
Move runtime-neutral contracts to declared owners, keep adapter mechanics with
adapters, migrate every consumer, then semantically retire `shared`. Physical
deletion follows observed-zero evidence.

### `security` placement

FABLE treated security-method improvement as capability evolution; SOL treated
the actual scan/report as validation evidence.

Resolution: the current skill is evidence with a separately authorized
mutating mode. Reusable improvements to security methods remain later
capability-evolution proposals; the evidence skill is not a validator and
cannot accept risk.

### `goals` terminology

Both agreed that project fitness is not a persistent Goal campaign. They
disagreed only on timing and compatibility.

Resolution: pin vocabulary first, then rename the semantic skill to `fitness`.
Advertise only `fitness`, keep a measured non-advertised `goals` alias, and
leave the unrelated `ao goals` CLI command unchanged.

### Kernel size

SOL rejected a universal line count as a proxy for loaded context. FABLE
preferred keeping the existing guard until a replacement exists.

Resolution: retain 250 lines as an interim warning/gate, then replace it with
an always-loaded byte/token and progressive-disclosure metric. The line cap is
not a permanent architecture axis.

## Blind spots incorporated

The final plan incorporates all material novel blind spots:

- single-mint intent-byte transport;
- non-self-certifying proof-epoch activation;
- dirty pre-publication recovery;
- portfolio reachability and live-model behavior;
- installed-estate version negotiation;
- semantic retirement before physical deletion;
- observed effect receipts;
- safe resting states at every tranche boundary; and
- explicit acknowledgement that deterministic text contracts do not prove
  stochastic agent compliance.

The last item remains residual risk. The plan measures it with frozen routing
and behavioral samples rather than claiming it can be compiled away.

## Synthesis validation

The final synthesis was checked independently of the wizard prose:

- the live tree contains 49 skill sources;
- the final matrix contains the same 49 slugs exactly once;
- markdown lint passed for the plan, duel report, Go audit, architecture
  contract, and component map;
- `git diff --check` passed;
- `make docs-check` passed, including 424 links, exact 49-skill metadata
  coverage, and the documentation release gate;
- `make regen-check` did not run its owner: it exits 126 because
  `scripts/regen-all.sh` is not executable; and
- direct `bash scripts/regen-all.sh --check` confirmed pre-existing drift in
  the `implement` Codex twin and hashes, GC projections, and generated pack
  manifest.

The last two results are not plan-document failures. They are concrete T0
check-liveness and dirty-baseline defects and are therefore retained as
blocking evidence rather than repaired during this analysis.
