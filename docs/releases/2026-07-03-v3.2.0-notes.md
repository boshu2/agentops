# AgentOps v3.2.0

## Highlights

AgentOps 3.2 is the **verification-keystone** minor: the cross-family review loop that guards this repo is now a first-class, portable product surface. `ao verify` becomes the canonical front door — one verb to review a change, bind the verdict to the provenance ledger, and prove it later — with `ao verify init` installing the same pre-push verdict ratchet in any repo, `ao verify stats` pricing the cost of verified-done, and `ao verify receipts` rendering the proof page. Behind that front door the reviewer hardened into a standing multi-model service with honest failure labels (outage-only failover, REBOUND re-authorization for byte-identical rebases, an opt-in strict two-family quorum), and the membrane gained memory: catches are recorded, recalled by domain, and honestly triaged, with the escape→derived-check loop proven end-to-end on the shipped binary. Around that core the CLI shed the cathedral — the default build is now the verification + bookkeeping spine, the speculative corpus-flywheel moved behind build tags, and `ao rpi`, `ao recall`, and the bd/Dolt tracker are gone. See [docs/3.2.md](../3.2.md) for the full narrative.

## Upgrade Notes

- Standard installs upgrade in place — `brew upgrade agentops` or re-run the install one-liner for your runtime (README §Install). No data migration.
- Removed: the `ao rpi` command surface (ADR-0009 executed). The operating loop ([docs/architecture/operating-loop.md](../architecture/operating-loop.md)) plus the process skills are the navigation path; `/rpi` remains as a skill.
- Removed: `ao recall` and `ao memory ingest-claude` (the v1 unified-memory experiment). Recall is consumed from the coexisting open-source tools (cass / cass-memory) rather than rebuilt in-tree.
- Removed: the bd/Dolt tracker lane. `br` (beads_rust) + `bv` are canonical; the issue ledger is git-JSONL. `bd` wrappers and docs were swept.
- Changed: the default `ao` build ships the spine only. Corpus-flywheel and legacy command families (`harvest`, `refinery`, `mind`, `turn`, `harness`, `operator`, `curate`) now require an explicit `-tags "flywheel legacy"` build; the default binary omits them and `ao --help` groups experimental surfaces separately.
- Deprecated: `ao inject` as the context query door — skills and docs now point to `ao lookup` (the command itself still ships in 3.2).
- New verbs worth adopting: `ao verify`, `ao done` (verdict-referenced bead close), `ao provenance show`, `ao pawl {up,health,route,metrics}`, `ao wiki`, `ao plan-pawl decide`.

## Product Areas

### Install, Upgrade, and Distribution

- Added: a spine-only install tier — the default `ao` build carries the verification + bookkeeping core, with corpus-flywheel and legacy commands behind `flywheel`/`legacy` build tags.
- Changed: the pre-push path is safer under load — installs are worktree-safe with a self-healing hook chainer and `core.bare` heal, concurrent local pushes serialize, and installed fast-forward hook candidates are preserved.
- Changed: `ms-reindex` ships with a post-merge hook installer so the skill-search index stays current mechanically.
- Changed: GitHub Actions checkout bumped from v4 to v7 across workflows.
- Fixed: workflow install/drift validation scripts guard the `.claude/workflows` install path against marker and content drift.

### CLI and Operator Commands

- Added: `ao verify` — the canonical verification verb over the cross-family review engine, with `init` (portable pre-push verdict ratchet + chain verify for any repo), `stats` (cost-of-verified-done from the ledger), `receipts` (portable proof page), and a per-repo config file with `--show-config`.
- Added: `ao done` — verdict-referenced bead close with a warn-first close-rate gate; falls back to the origin/main ledger when the local one lags.
- Added: `ao pawl` service surface — `up/down/health/route/metrics` for the standing reviewer service, plus `ao pawl review` for one-shot reviews that work zero-config on a stranger's repo.
- Added: `ao provenance show` (per-SHA/bead verdict lineage) and `ao provenance mine-session` (native incremental session-log miner).
- Added: `ao wiki` — the OpenKB port: `init/use/add/remove/recompile/lint/status`, gold-wiki compilation from `.agents/`, and verdict-gated publish bound to a content digest.
- Added: `ao plan-pawl decide` (deterministic duel decider), `ao governor budget` (error-budget burn-rate), `ao scenario evaluate`, `ao worktree create`, `ao beads verify-acceptance`, `ao rehydrate`, and `ao skills retire`.
- Changed: session-continuity commands consolidated under `ao session`; eval-family commands consolidated under `ao eval`; the quick-start reaches a first verdict in one command.
- Changed: `--config` is fail-closed — the flag names THE config file, with no silent home-directory leak.
- Fixed: gate checks accept `--scope range` and emit non-empty `--json` FAIL detail for landing loops.
- Removed: the `ao rpi` command surface — the operating loop and skills are the navigation path (ADR-0009).
- Removed: `ao recall` and `ao memory ingest-claude` — recall is consumed from cass/cass-memory instead of rebuilt in-tree.
- Removed: the dead `ao cron` compatibility shim; `turn`, `harness`, `operator`, `harvest`, `refinery`, `mind`, and `curate` moved behind archive build tags.

### Skills and Workflows

- Added: a durable 15-skill spine partition (`spine: true` with a behavioral GOALS gate) separating the proven product loop from experimental skills.
- Added: the `ms` skill — meta_skill search/load doctrine (MCP consume, CLI writes) — surfaced in session bootstrap and folded into the discovery/plan/skill-builder decision points.
- Added: plan-pawl duel integration — `/discovery` gains `--duel/--no-duel/--duel-rounds`, pre-mortem gains the duel checklist, and fanout-class plans get a cross-family acceptance gate before beads are written.
- Added: `behavior-first-planning` and `pre-land-refuters` skills; `dual-pane-atm` absorbs the mixed-model duel; `account-rotation` unifies host-routed account switching.
- Changed: the skill catalog was consolidated hard — the corpus prune folded 39 sources into 21 targets (105→65), then 70→63 with six skills folded into canonical owners; `ao skills retire` makes retirement deterministic via the dispositions ledger.
- Changed: six corpus-flywheel skills plus `evolve`/`autodev`/`acfs` demoted to a new experimental tier (Codex twins dropped for demoted skills).
- Changed: substrate-skill sprawl folded 13→5 via the dispositions ledger.
- Changed: all 50 trigger-marker offenders cleared and held by a new `skill.triggers` gate; folded-skill redirects are gate-checked for validity.
- Fixed: retired `bd` tracker vocabulary swept for `br` across the skill corpus and workflows, with a regression gate.
- Fixed: skill fences avoid start-of-line `#` comments that the ms normalizer garbles.
- Removed: the standalone `caam` skill (folded into `account-rotation`) and other retired slugs per the dispositions ledger.

### Codex and Runtime Integrations

- Added: task-packet and run-receipt JSON Schemas enforced at runtime — dispatch validates the packet, executes `required_commands`, and records results in the receipt.
- Added: dispatch security hardening — packet-injected auth env is rejected and dispatch paths are bounded to cwd/`allowed_paths` roots.
- Added: a Codex image health doctor with per-check timeouts and slow-check reporting.
- Changed: Codex twins are now generated self-contained from source (killing the hand-mirror whack-a-mole), with a pointer-exemption mechanism, byte-verify drift gate, and content-divergence gates extended to SKILL.md bodies and references.
- Changed: twin regeneration is scoped to the spine set — a ~70% regen cut for routine landings.
- Fixed: a shared fail-closed `codex-exec` runner library centralizes stall/echo defenses for every non-pawl caller.
- Fixed: rebase auto-merge damage in generated Codex manifests is repaired and guarded.

### Knowledge Flywheel, Search, and Memory

- Added: membrane memory — `ao membrane catch` records panel catches at the verdict chokepoint, `ao membrane recall` retrieves them by domain (`--include-catches` injects them into prompts), and `ao membrane triage` is an honest two-axis recurrence instrument.
- Added: the escape→derived-check loop is proven end-to-end on the shipped binary — an escape compiles into a draft constraint, activation enforces it at the gate, the derived check auto-loads by domain and cites the escape, and learned constraints travel to CI and clean clones.
- Added: real token accounting — per-bead token capture, `ao yield tokens` (Claude and Codex transcripts, deduped by response id, loud on absent usage), and an SPC governor (`ao governor budget`) with a two-sided noise band.
- Changed: retrieval gained a gold layer — `ao lookup --gold` reads the OKF gold wiki compiled from `.agents/`, `--pointers` gives bounded retrieval, and a cold-start ε-exploration floor keeps low-traffic knowledge reachable.
- Changed: gold findings are ranked by utility with token-match relevance weighting so natural-language queries surface them.
- Fixed: the provenance ledger append is serialized under a cross-process lock — no more chain forks under concurrent landings.
- Removed: the unproven memory-moat machinery (per ADR-0004 honesty) — the membrane stays; the moat claims went.

### Eval, Validation, and Release Gates

- Added: REBOUND verdicts — a byte-identical rebase re-authorizes via patch-id + lineage + gate-green instead of burning a full re-review; honored by the portable push-gate and CI, with keep-ref re-verification for orphaned reviewed commits.
- Added: an opt-in strict two-family cold quorum that refuses to degrade (honest-UNAVAILABLE until a second strict-eligible family exists), plus an outage-only cold reviewer failover chain with an explicit degraded label.
- Added: an evidence-quality floor for CONFIRMED verdicts (finding-or-attestation + genuine-run marker) and a live-smoke verify mode that puts runtime evidence in the review packet.
- Added: the verification-membrane eval — false-done catch rate over deterministic oracles with cross-family verifiers, real-false-done trap tasks, escape-harvest tooling, and a measured local-MLX eval membrane (100% per-task concordance vs codex on the eval path; prod gate stays frontier cross-family).
- Added: scenario A/B got environment-level arm isolation (macOS sandbox-exec), deterministic answer-key grading, a ceiling pre-screen, and absolute task-success judging; moat-claim scorecards hard-reject ineligible evidence.
- Added: a wave of deterministic gates — full race suite on push-to-main, provenance hash-chain verification, live-doc CLI-snippet resolution, skill-refs across all docs, a demoted-claims honesty lexicon, a script-preamble ratchet, an ADR-registry check, fail-closed pinned golangci-lint, and a shell-portability gate.
- Added: the land pipeline hardened — a single-writer land lane with a branch submit queue, deterministic land wrapper, staged-scope pre-commit guard against concurrent-lane contamination, and first-class per-item consumed markers in the next-work queue.
- Changed: the default gate routes to the Go release authority (`ao gate check`) on the ship path, and a report-only CI verdict backstop re-verifies tip verdicts.
- Changed: pawl reviews scale their timeout with diff size, and `#trivial` waivers verify the diff is genuinely provenance-only.
- Changed: the standing pawl service is the default review route — warm tri-model panes (Claude + Codex + AGY) with capability-adaptive routing, self-healing respawn/reroute, and p50/p95 + agreement SLO metrics.
- Fixed: the pawl records each pane's actual verdict instead of fabricating REFUTED from a timeout, collects all verdicts instead of guillotining on the first REFUTE, and uses delivery-based sends after the unreliable engagement gate was removed.
- Fixed: cold codex reviews are echo-safe with self-explaining diagnostics on backgrounding-reap, and a hijack guard refuses verdict binds when the worktree HEAD moved mid-review.
- Fixed: a macOS portability sweep across the bats suites and release scripts (BSD `wc`/`stat`/`find`/`sed` divergences) — the full suite passes on both platforms.

### Security, Privacy, and Supply Chain

- Security: tar extraction gained explicit containment — absolute paths rejected, canonical path-inside assertion, typed rejects.
- Security: a fail-closed pre-push path guard scans the full tree for private artifacts, and `ao corpus scan` detects deny-listed/PII content before it ships.
- Security: cwd-relative script execution routes through a trust chokepoint (`aoBinaryInside` guard), and Codex dispatch rejects packet-injected auth environment variables.
- Security: the SDLC provenance ledger is tamper-evident — hash-chain verification runs as a local gate at the pre-push boundary and ledger appends serialize under a cross-process lock.
- Security: JSONL storage helpers moved to a loud-failure buffer policy with fsync-safe atomic writes and parent-dir fsync after rename.

## Known Issues

- The full-tier local gate (`ao gate check --full`) carries two environment-dependent reds on the primary dev machine — `full.worktree-disposition` (many attached session worktrees; janitor tracked in age-ym4b) and `doctrine.memrl-health` (local `.agents` citation-feedback backlog) — both green on a fresh clone, and the push-path gate set is green. The four tree-level reds age-hl9q tracked (go.lint, skill.heal-strict, doctrine.flywheel-proof, always.three-gap-supergate) were fixed in this release.
- The IMAGE-CORE acceptance recipes (`images/claude`, `images/gemini`) still reference the pre-consolidation skill corpus, so their `verify.sh` acceptance checks fail against the 64-skill tree (12 retired slugs; stale 65-slug count). The live install manifests (`.claude-plugin`, `.agy-plugin`, `.codex-plugin`) are correct and the publish path does not run these verifiers; the recipe refresh is tracked in age-085q.
- One historical commit on main (5b064b28b) carries a wrong author email from a lane that predated the identity fix; it is cosmetic (GitHub misattribution on that single commit) and deliberately accepted rather than rewriting released history (age-jhal).
- Cold cross-family review cannot verdict diffs whose `git show` exceeds ~65KB (deletion-heavy commits); the warm service handles larger diffs, and the strangler-split landing pattern is documented for the rest.
- The strict two-family cold quorum reports honest-UNAVAILABLE until a second strict-eligible reviewer family is graduated (AGY remains benched for strict validation).
