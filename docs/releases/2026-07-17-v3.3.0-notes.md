## Highlights

AgentOps 3.3 is the Cathedral Cut. It restores the original trust boundary:
shape one behavior, run one bounded experiment, validate the exact candidate
from fresh context, persist the verdict, and stop. The release removes the
control plane that made Git delivery, retries, queues, and closure part of
AgentOps correctness.

This release removes public command surfaces despite the minor version number
— a knowing semver deviation while the 3.x audience is small. Read the
Breaking Changes section and [docs/UPGRADING.md](../UPGRADING.md) before
upgrading.

## Upgrade Notes

- If you ever ran `ao verify init`, delete the `AGENTOPS-VERIFY-RATCHET` block
  from that repository's `.git/hooks/pre-push` (restore `pre-push.agentops-orig`
  if one was set aside). The 3.2 hook calls removed commands and blocks every
  push with a misleading "ao too old" error; `ao verify init --remove` no
  longer exists.
- Move `~/.agentops/config.yaml` (and any `./.agentops/config.yaml`) to
  `~/.agents/ao/config.yaml` / `./.agents/ao/config.yaml`. Legacy paths are
  still read as a fallback for this release, with a deprecation warning.
- Refresh your install: plugin installs keep working (update the bundle through
  your runtime), npx installs re-run `npx skills@latest add`, and contributors
  can switch to one canonical checkout plus `ao skills link`; see
  [the migration guide](../MIGRATION.md).
- Replace folded skills and removed CLI lifecycle commands before the next
  release removes their one-release tombstones.
- Migrate verdict consumers to `verdict.v2` and `subject-manifest.v1`.

## Breaking Changes

- RPI dispatches Plan, Implement, and fresh Validate at most once, then reports
  `PASS`, `FAIL`, `NOT_PROVEN`, `NOT_PLANNED`, or `NOT_BUILT` and stops.
- AgentOps no longer owns retry, queue, claim, Git, closure, release, or delivery
  state. Repository and caller policy own those transitions.
- Discovery, behavior-first-planning, and goal-design are folded into Plan;
  Crank and controller/delivery skills are removed.
- Semantic `ao validate` and the Pawl, landing, governor, tracker-wrapper, and
  lifecycle CLI families are removed behind non-mutating tombstones.

## Product Areas

### Install, Upgrade, and Distribution

- Added: `ao skills link` installs one canonical corpus across portable and
  detected runtime roots without overwriting foreign skills.
- Changed: three supported install paths — `npx skills add` (universal across
  coding agents), runtime plugins for Claude Code and Codex (managed bundles),
  and checkout + `ao skills link` for source-tracked installs.
- Removed: the 3.x curl installer scripts are refusing tombstones.

### CLI and Operator Commands

- Changed: the default CLI is a deterministic check, inspection, generic
  provenance, goal-measurement, session-evidence, and skill-linking tool.
- Removed: lifecycle, semantic-validation, retry, queue, Git, and delivery
  controllers; major public names have inert one-release tombstones.
- Fixed: `ao doctor` now checks the release binary, exact source-skill links,
  optional provenance integrity, and host safety without implicitly running the
  old plugin, tracker, reviewer, search-index, OpenClaw, or repair engine.
- Fixed: CLI tests isolate tmux cleanup from the operator's inherited server.

### Daemon, Scheduling, and Factory

- Removed: AgentOps correctness no longer depends on a daemon, scheduler, queue,
  factory controller, or automatic continuation engine.
- Changed: caller-selected runtime adapters may dispatch explicit work once but
  cannot create core lifecycle state.

### Skills and Workflows

- Changed: the load-bearing core is `rpi`, `plan`, `implement`, and `validate`;
  `learn` is optional later analysis.
- Refactored: the 48-skill corpus uses metadata as the sole source for registry,
  router, graph, counts, and runtime projections.
- Fixed: every canonical skill passes the recalibrated deep strict audit.

### Codex and Runtime Integrations

- Changed: Codex release twins and Gemini bundles remain generated distribution
  artifacts while source links are the active local path.
- Fixed: runtime manifests, descriptions, prompts, versions, and inventories now
  describe the Cathedral Cut instead of 3.2 lifecycle machinery.
- Removed: the unreferenced `.agy-plugin` 12-skill copy; `images/gemini` remains
  the generated compatibility bundle.

### Hooks and Lifecycle

- Removed: pre-push semantic admission and AgentOps-owned lifecycle transitions.
- Changed: repositories may keep ordinary deterministic hooks and CI according
  to their own policy; those checks do not create semantic verdicts.

### Knowledge Flywheel, Search, and Memory

- Changed: Learn and the read-only flywheel views remain off the critical path.
- Removed: automatic promotion, activation, nudge, close-loop, and memory-sync
  authority from the supported default surface.

### Eval, Validation, and Release Gates

- Added: structural Cathedral Cut conformance and runtime-neutral scenario
  coverage checks.
- Refactored: release smoke and JSON contracts exercise only retained commands
  plus inert tombstones.
- Fixed: generated CLI heading counts and public canaries match the cut surface.

### Docs and Onboarding

- Docs: README, migration, upgrading, image, day-2, and release documentation now
  use one checkout plus symlinks and the one-pass loop.
- Removed: an unreferenced stale vibe-kit manifest and obsolete controller-era
  upgrade instructions.

### Security, Privacy, and Supply Chain

- Security: exact subject identity includes file kind, deletion, executable bit,
  symlink target, normalized path, and content digest.
- Changed: release publication retains checksums and attestations without making
  release state part of semantic validation.

### Contributor/Internal Refactors

- Refactored: generated skill artifacts and CLI docs regenerate from their
  declared canonical owners.
- Fixed: concise skills no longer fail quality checks for omitting ceremonial
  sections or optional packaging directories.

## Known Issues

- Removed command tombstones and legacy plugin installers intentionally remain
  for one migration release. They are compatibility notices, not live control
  paths, and are scheduled for deletion in the next release.
