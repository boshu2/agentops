# 3.0 Release Trust Cut Sheet

Date: 2026-05-17

This cut sheet records the release-owner disposition for `soc-m6v5.9.10`, the
3.0 release-trust baseline. It is intentionally narrower than `soc-n55w`: it
unblocks the 3.0 go/no-go path without claiming that local CI has become a
perfect offline clone of GitHub Actions.

## Required 3.0 Verdict Path

For the 3.0 candidate SHA, use this command sequence as the release truth set:

```bash
scripts/ci-local-release.sh --release-version 3.0.0
scripts/verify-release-ci.sh <tag-or-release-sha>
```

`scripts/ci-local-release.sh --release-version 3.0.0` is the canonical local
pre-tag gate. It runs the full local release surface, writes release artifacts,
and fails if the release readiness score is below threshold.

`scripts/verify-release-ci.sh <tag-or-release-sha>` is the exact-SHA remote
authority. A 3.0 release is not GO until the GitHub `Validate` workflow is
green for the exact candidate or tag SHA.

## Waiver For `soc-n55w`

`soc-n55w` remains open. The accepted 3.0 waiver is:

- Local-only green is not sufficient for 3.0 release GO.
- `scripts/ci-local-release.sh --release-version 3.0.0` is required before tag.
- `scripts/verify-release-ci.sh <tag-or-release-sha>` is required after push.
- If either command fails, release status is NO-GO.

This waiver is acceptable for 3.0 because the release process now treats
exact-SHA `Validate` as mandatory. `soc-n55w` should still implement a single
local command whose exit code matches the CI-blocking verdict set when that
work is scheduled.

## Go/No-Go Rule

`soc-m6v5.9.6` may report GO only when the 3.0 candidate has:

1. Passing local release artifacts from `scripts/ci-local-release.sh
   --release-version 3.0.0`.
2. Passing exact-SHA GitHub `Validate` evidence from
   `scripts/verify-release-ci.sh <tag-or-release-sha>`.
3. Any HIL target gaps recorded in the release readiness artifact as pass or an
   explicit waiver.
