## Highlights

AgentOps 3.8 refactors the engineering workflow across 13 skills: 11 existing
skills are updated and two are new, Review and Orchestrate. It builds on the
native workflow introduced in 3.7: accepted intent, implementation and checks,
fresh independent judgment, then finish. The menu grows from 34 to 36 skills;
native coding still requires none of them.

Enter the workflow wherever the work needs you. Implement a clear request
directly, use Plan to resolve uncertain behavior or scope, ask Review for
advice on existing work, or use Orchestrate when coordination is needed.
Planning is optional; independent acceptance of the implemented result remains
part of the workflow.

Reviewed project knowledge can live in Git under a caller-selected `.context/`.
An authored map points to topic pages and current source owners. Drafts and
review evidence remain in protected external storage. Implement also gains
optional service-operation methods, and installer and runtime-probe repairs
make their reported evidence more precise.

## Workflow and Entrypoints

The six primary entrypoints are Plan, Implement, Review, Validate, Orchestrate
and Memory. They are independently usable, not a required sequence. Research,
Test and Refactor also serve focused tasks. Select guidance for the uncertainty
and complexity of the work, using the intent already recorded in the issue or
conversation. Plan can resume accepted decisions after an interruption and
challenge a consequential assumption without restarting settled work.

Review supplies advice. Fresh Validate judges the exact candidate against the
accepted behavior. Repair a demonstrated failure or obtain missing evidence,
then request fresh judgment of the updated candidate. A test pass does not
replace acceptance, and acceptance does not perform your repository's delivery
steps. See the [README workflow and examples](https://github.com/boshu2/agentops/blob/main/README.md#workflow).

Alongside the new Review and Orchestrate skills, this release updates Agent
Native, CC Hooks, Domain, Implement, Memory, Plan, Premortem, Reality Check,
Research, Test and Validate. Shared context and operations guidance are part
of that refactor: Memory owns reviewed reuse, and Implement includes service
operations methods.

## Upgrade Notes

- Update your managed plugin or selected source checkout using the
  [update guide](https://github.com/boshu2/agentops/blob/main/docs/install-day2-ops.md#update), then start a fresh session.
  Use the host's native inventory for registered skill names. Source links,
  installed copies, custom roles and hooks have separate update paths.
- Existing 3.7 command and skill names remain available. If upgrading from
  3.6 or earlier, follow the [migration guide](https://github.com/boshu2/agentops/blob/main/docs/MIGRATION.md) and
  [3.7 release notes](https://github.com/boshu2/agentops/blob/main/docs/releases/2026-09-13-v3.7.0-notes.md) for the earlier removals.
- Select Review for advice and fresh Validate for acceptance of an exact
  candidate. Orchestrate is optional guidance for existing native coordination;
  it introduces no service or scheduler to install.
- Project `.context/` is opt-in. Admit only public or already-cleared material
  after the required support and disclosure review. Existing external context
  routes remain supported; using `ao config context` still requires its explicit
  policy, identity bindings and native BD maintenance anchor.
- Preserve existing `.agents/` evidence and user-owned installed directories.
  Read-budget guards and Codex role registration remain separate opt-ins;
  installing a plugin alone does not enable those optional features.

## Product Areas

### Skills and Workflows

- Added: Review examines a supplied subject without editing it and returns
  advice with source evidence, checked scope and gaps. It clarifies unresolved
  intent before choosing advice or handing acceptance to fresh Validate.
- Added: Orchestrate reconciles native assignments and usable prerequisites,
  coordinates disjoint work, integrates the candidate and assigns fresh
  exact-content judgment. Trackers, runtimes and Git retain their authority.
- Changed: Plan recovers settled choices, accepted examples, active scopes and
  one open question from existing intent or handoff. Optional challenge and
  probes have explicit stopping conditions; inherited evidence is rechecked
  when its source changes.
- Changed: Memory supports reviewed Git-shared project topics as well as
  external bundles. Its map directs selective reading, and later work must
  establish whether reused guidance helped.
- Added: Implement's operations reference covers service promises and SLOs,
  delivery evidence, user-visible incident recovery, bounded fault experiments
  with restoration, and full-cost comparisons for toil automation.

### CLI and Operator Commands

- Changed: `ao config context` accepts the canonical direct
  `<consumer-root>/.context` as an explicitly bound bundle. External bundles
  remain supported. Other consumer-overlapping bundle paths are refused, and
  staging/evidence roots remain disjoint from the consumer, bundle and Git.
- Changed: Skill discovery metadata distinguishes implementation, advisory
  review and acceptance judgment while preserving named Validate requests.

### Install, Upgrade, and Distribution

- Changed: The metadata-derived skill inventory grows from 34 to 36 with
  Review and Orchestrate. Claude, Codex and Gemini package projections carry
  the current inventory and 3.8.0 version surfaces.
- Fixed: Installed-skill edit-guard and `cc-hooks` installers use unique backup
  names, preserving settings across rapid repeated installs.
- Docs: Installation and recovery guidance distinguishes managed plugins,
  selected source links and copied skills, including dependencies and stale-copy
  conflicts. Research, Test and Refactor lead the curated skills.sh groups.

### Codex and Runtime Integrations

- Fixed: The headless adapter preserves native structured output and rejects
  substantial prompt reflection, including reflected assistant JSON events.
  Marker strings and output length no longer stand in for execution evidence.
- Changed: Runtime qualification distinguishes structural packaging, native
  discovery/loading and observed execution. Help output and source-link creation
  establish only their stated scope; selected roles and hooks need separate
  activation and upgrade checks.
- Docs: A selected project install through Skills 1.7.0 was exercised in
  Cursor CLI 2026.09.18-9a7762b. Research, Plan, Implement and Test appeared in
  the native picker; Research, Implement and Test were loaded in native sessions.
  A bounded repair passed all 10 regression tests and independent boundary
  probes. Explicit reinstall recovery and a local-source upgrade followed by
  a fresh session were also checked.

### Eval, Validation, and Release Gates

- Fixed: Skill-request tests preserve explicit invocation and refusal
  assertions. Runtime and release probes require observed execution evidence
  before reporting their live checks as passed.
- Fixed: Aggregate coverage, proxy tests and executable entrypoints received
  deterministic test repairs. Review routing fixtures cover design advice,
  change advice and acceptance requests.
- Changed: Structural conformance and live behavioral observations remain
  separately reported. Passing repository gates does not establish universal
  skill efficacy or a semantic acceptance verdict.

### Docs and Onboarding

- Changed: The README makes the workflow and its entrypoints visible: start
  directly with implementation when intent is clear, select planning or
  coordination when needed, and use feedback from fresh judgment to repair
  failures or fill evidence gaps. Migration and routing guidance retain native
  ownership boundaries and optional shared context.
- Fixed: Published catalog, schema and setup links point to their repository
  sources so the documentation site's strict build can resolve them.
- Changed: Documentation dependencies and pinned GitHub Actions were refreshed
  across the v3.7.0-to-v3.8.0 interval.

## Known Issues

- Package conformance and selected live trials do not establish efficacy for
  all 36 skills or tasks. No generalized outcome or token-cost improvement is
  claimed for Review, Orchestrate, challenge or shared-context reuse.
- Restricted-source enforcement remains unavailable. Context routing checks
  policy and identity bindings; project Markdown, prompts and same-user
  worktrees do not enforce source access or model egress restrictions.
- Codex's reader role inherited its writable parent's sandbox in earlier live
  testing. Enforced reader write confinement remains unproven. Hook coverage
  is limited to supported native read and shell paths.
- Native discovery, loading and execution must be established for the chosen
  host, version and installation path. The selected Cursor CLI trial does not
  qualify all 36 skills, Plan execution, desktop use or automatic remote
  updates. Gemini/Antigravity package validation does not prove native loading.
- Prompt-reflection detection is a content heuristic. An adapter's successful
  exit or accepted structured output cannot establish semantic correctness or
  fresh independent acceptance.
