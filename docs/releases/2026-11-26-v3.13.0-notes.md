## Highlights

AgentOps 3.13.0 makes one check honest about what it covered. `ao gate check`
picks its checks from the files a scope says changed. On the default scope,
with edits that were not yet committed, it printed a green summary while the
checks for those edits never ran. It now names the paths it left out and says
how to include them.

- **A green gate run says what it skipped.** After the `not run:` line, a fast
  run prints, for example, `not considered by routing: 2 uncommitted paths
  outside scope head (1 modified, 1 untracked)`, the first three paths and the
  way to route on them. If the worktree cannot be listed, the run says its
  coverage is unknown instead of reporting zero.
- **Orchestrate's work packet is a template.** The packet contract was one
  sentence listing 17 fields. It is now a fenced template with one field per
  line. The fields and the "launch none" rule are unchanged.
- **A measurement that found no effect.** Sweep 5 crossed the operating
  contract in the request with the RPI skill loaded by name, on four trap
  tasks, 48 runs on Claude Opus 5.5. All four arms scored the same. The report
  says why that result is narrow: three tasks are at ceiling and one fails in
  every arm.

The gate change matters if you run `ao gate check` in an AgentOps checkout or
a fork. Skill users get the Orchestrate template and nothing else that changes
behavior.

## Upgrade Notes

- Update the plugin, the npx install or Homebrew as usual. In Claude Code, if
  `claude plugin update` reports no change, uninstall and reinstall the plugin
  to refresh its copy. Start a new session afterward.
- No skill, command or flag is added, removed or renamed. Exit codes, the
  default scope and the checks a run selects are unchanged.
- `ao gate check --json` gains one optional key, `run.uncommitted_outside_scope`.
  It is omitted when nothing is outside the scope. If you read the human
  summary line by line, expect a new line starting `not considered by routing:`
  or `routing coverage unknown:` after the `not run:` line.
- In a source checkout, run `git pull --ff-only`, then rebuild `ao`
  (`cd cli && go install ./cmd/ao`) to get the gate note. Linked skills pick up
  the Orchestrate change without relinking.
- Upgrading from 3.11 or earlier: read the
  [3.12.0 release notes](https://github.com/boshu2/agentops/blob/main/docs/releases/2026-11-10-v3.12.0-notes.md)
  first. Four skill names were removed there.

## Product Areas

### CLI and Operator Commands

- Fixed: `ao gate check` says when its routing left uncommitted work out. A
  fast run on the default scope (`head`) reads only the last commit, so
  uncommitted edits selected no checks and the summary was still green. The
  summary, the dry-run plan and `--json` now name those paths.
- Fixed: the advice follows what the scope reads. For modified files it is
  `--scope worktree`. For new files it is `git add`, plus `--scope worktree` on
  the `head`, `upstream` and `range:` scopes, which compare commits and so do
  not see a staged file.
- Added: `run.uncommitted_outside_scope` in `--json`, with `modified_count`,
  `untracked_count`, up to three `examples` and `error`.
- Unchanged: `--full` prints no note, because it runs every check and does not
  route.

### Skills and Workflows

- Changed: [Orchestrate](https://github.com/boshu2/agentops/blob/main/skills/orchestrate/SKILL.md)'s
  packet contract is a fenced template with one field per line.
- Changed: the headless Claude example in
  [Validate's model-dispatch reference](https://github.com/boshu2/agentops/blob/main/skills/validate/references/model-dispatch.md)
  takes the model ID from a variable instead of naming a model that goes stale.

### Eval, Validation, and Release Gates

- Added: [estate ablation sweep 5](https://github.com/boshu2/agentops/blob/main/evals/estate-ablation/SURVIVORS.md)
  and its per-run results. Hidden tests passed on 9 of 12 runs and a false PASS
  was written on 3 of 12 in every arm; all 12 false passes are one task.
  `SURVIVORS.md` also gains a section-by-section table for the current
  contract. No contract text is removed.
- Added: a test that the curated release notes and the changelog section for
  the current version use absolute links, since both become the release page.
- Changed: CI builds with Go 1.27.4, the toolchain `go.mod` already names, and
  `actions/setup-go` 7.1.0.

### Docs and Onboarding

- Added: [a three-part agent harness](https://github.com/boshu2/agentops/blob/main/docs/patterns/agent-harness-split.md),
  a pattern page: skills for judgment, a deterministic CLI for facts, host
  extensions for capabilities and governance. It is a proposed design, not a
  measured result.
- Removed: the `docs/upgrade-packets/2026-unified-harness-patterns/` packet.
  The pattern page replaces it.
- Changed: the docs-site Python dependencies are updated.

### Install, Upgrade, and Distribution

- Changed: the release workflow builds with Go 1.27.4 and `actions/setup-go`
  7.1.0. Install paths and package names are unchanged.

## Known Issues

- No scope routes on an untracked file until it is added. The note says so
  when it applies.
- The Orchestrate template is not measured. No eval case covers the packet
  contract, so whether agents fill it more completely is unknown.
- Sweep 5 shows no effect on four tasks only. It does not exercise the
  contract's limits on review rounds, helpers or artifacts, and its 48 reply
  grades were spot-read and counted by pattern, not checked one by one.
- Every measurement is on Claude Code with Claude Opus 5.5. Nothing is measured
  on Codex, Gemini, Cursor or another Claude model.
- The loading limits listed in the
  [3.12.1 release notes](https://github.com/boshu2/agentops/blob/main/docs/releases/2026-11-11-v3.12.1-notes.md)
  still apply: no description line changed in this release.
