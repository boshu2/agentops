## DONE #1 — the skills overlay snapshot (CURATED, pinned)

`overlay/.claude/skills/` now ships a PINNED, self-contained copy of a **CURATED
core-loop subset** of the repo's `skills/` (25 skills, ~338 files, zero symlinks),
plus a `PROVENANCE.md` note. Regenerated by
`assets/scripts/sync-overlay-skills.sh` (`--check` mode = drift detector).

**CURATED, not full — DECISION FLAG.** The runbook §3.1 originally specced "all
post-rip lean `skills/**`" (~80 skills). The finalize pass instead ships a curated
core-loop set: the loop runtime an agent actually invokes — `ao rpi` and its inner
phases (`research`/`plan`/`implement`/`crank`/`validate`/`validation`), the outer
loop (`evolve`/`post-mortem`/`pr-validate`/`council`/`harvest`), corpus
(`inject`/`compile`/`curate`), strategy+standards+vocabulary
(`goals`/`standards`/`domain`), supporting loop skills
(`discovery`/`scope`/`handoff`/`recover`/`status`/`provenance`), and the `shared`
dependency the loop skills reference.

- **Why curated:** an agent GC spawns to run the AgentOps loop needs the loop
  runtime, not all 80 author/maintenance/meta skills (readme, oss-docs, grafana,
  llm-wiki, skill-builder, etc.). Shipping all 80 bloats every agent workdir and
  copies skills no loop step invokes. The curated set is derived from what the
  pack's own prompts/formulas actually call (`ao rpi`, `/plan`, `/council`,
  `/pr-validate`, `/post-mortem`, `/evolve`, `/harvest`, `ao inject`).
- **Tradeoff vs the runbook's full-mirror stance:** a curated list is a small
  second inventory (the disease CLAUDE.md warns about). Mitigation: the set is a
  single explicit `CURATED_SKILLS` array in `sync-overlay-skills.sh`, and the
  sync/`--check` mechanism makes adding a skill a one-line edit + re-run. Widen to
  the full set by replacing the array with a `skills/*/` glob if a deployment needs
  every skill at the agent.
- **Source of truth stays `skills/`.** The overlay is a derived snapshot, exactly
  like the installed `~/.claude/skills/` copies.

## DONE #2 — `ao validate --gate` (live)

`ao validate --gate` is implemented on `main` (PR #516) and rebased into this
branch. Exit contract: `0` = PASS/WARN, `1` = FAIL, `2` = internal/usage error;
`--strict` promotes WARN → exit 1. The refinery prompt's Validate phase references
it accurately, and the gate runs INSIDE `ao rpi` (not as a GC `check.max_attempts`
step — the THIN-SEAM correction keeps retry/fresh-agent-on-failure inside `ao rpi`).

## DONE #3 — install source pinned

`assets/scripts/install-ao.sh` pins the install to a specific release tag
(`AO_VERSION` default `v2.41.1`, env-overridable) and downloads the installer to a
temp file before executing it (no pipe-to-shell — keeps the script clear of the
repo dangerous-pattern gate). It scaffolds `.agents/` via `ao init` (idempotent).
PINNED, not pull-latest, per Decision 2 (City reproducibility).

## DONE #4 — settings.json reconciled to hookless-first

`overlay/.claude/settings.json` ships ONLY the GC coordination substrate hooks
(`gc prime`/`gc handoff`/`gc mail check`/`gc hook`), matching the gastown
reference overlay. The SessionStart `ao inject` hook was REMOVED: per docs/3.0.md,
AgentOps 3.0 ships zero hooks and context flows through the explicit `ao` CLI
channel — `ao rpi` runs `ao inject` inside its Research phase and the mayor calls
`ao inject --query` directly, so no harness hook is needed.

## Decoupling note (worktree CLAUDE.md, soc-2rtm0)

The in-CLI gc-bridge (`runtime=gc`) was REMOVED from `ao` in a prior wave. This
reference City is an **external GC pack** consumed by the standalone `gc` binary —
it does NOT depend on the removed in-CLI bridge. The seam is: `gc` (orchestration)
invokes `ao` (the loop) as a subprocess via order/formula/prompt commands.
