## Findings

1. **The task-noun/judgment-posture split.** Skills whose names read as tools
   for the task's noun route (`reality-check` for a claim audit, `swarm` for
   parallel dispatch). Skills encoding judgment postures the model considers
   native thinking (`premortem`, `validate`, `security`) never route — the
   model just does the thing, at high quality, without reaching for a tool.
   Routing correlates with perceived tool-ness, not applicability.
2. **The delivery-channel confound (the batch's key finding).** rt-06's agent
   never invoked `standards` yet produced perfectly convention-matching code —
   because `.claude/rules/go.md` (auto-loaded) carries the same content and
   repo precedent completes it. **MISSED ≠ doctrine-absent** when an alternate
   channel (rules auto-load, repo memory, CLAUDE.md) delivers the content.
   The product-relevant metric is doctrine-DELIVERY, not Skill-invocation;
   routing is the scarce factor exactly where no alternate channel exists:
   foreign repos, codex-side workers, bare API. v3 must measure routing in a
   channel-controlled fixture (a repo WITHOUT rules/memory) and on codex.
3. Every MISSED run still produced high-quality doctrine-consistent output on
   sonnet-in-this-repo. Consistent with wave-1's capability story: strong
   model + rich context ≈ ceiling on quiz-shaped and advice-shaped work. The
   harness's routing value concentrates down-stack, same as its capability
   value.
